Parcours NestJS · FR

La chaîne pour maîtriser NestJS, en français.

Sept étapes, de « Hello World » à une API sécurisée et testée. Chaque étape s'appuie sur une ressource en français et se termine par un jalon concret — pas seulement une vidéo à regarder. Tout est vérifié et à jour pour Nest v12.

~50 h de contenu · 6 à 8 semaines Docs FR + 2 playlists vidéo FR 7 jalons de code
01

Le modèle mental à avoir en tête

Tout le reste en découle. Nest n'est pas Express : une requête traverse une chaîne de couches bien ordonnées. Si tu places chaque concept au bon endroit, tout le reste devient prévisible.

Le piège classique : beaucoup deCodes essaient de faire l'authentification dans un contrôleur ou un service. La couche Guards existe pour ça. Idem pour la validation (Pipes) et la gestion d'erreur (Exception Filters).

02

Avant de démarrer

Coche ces prérequis : Nest suppose TypeScript et un minimum de confort HTTP.

Node.js
Version 20.19+ minimum. Tu as Node v24.22.1 installé — tu peux démarrer tout de suite.
TypeScript
À l'aise avec les interface, les décorateurs (@Injectable()) et les types génériques. 3 h de mise à niveau suffisent.
HTTP / REST
Savoir ce qu'est un GET, un POST, un code 200 / 400 / 401 et un corps de requête JSON.
JavaScript
Promesses, async/await, modules ES. Tu n'as pas besoin de DOM ni de React.
Outil
npm ou pnpm. Un client HTTP (Insomnia ou Postman) pour tester tes routes.
Base de données
À partir de l'étape 3 seulement : PostgreSQL via Docker, ou une instance locale.
03

La chaîne, étape par étape

Chaque étape a une ressource vidéo francophone principale et un complément en français. Ne saute pas d'étape : l'injection de dépendances et les DTO sont utilisés partout après.

  1. Étape 1 — Les fondations : Module, Controller, Service

    ~6 h
    • Créer un projet avec la CLI Nest et comprendre la structure src/.
    • Comprendre l'injection de dépendances : le décorateur @Injectable() et le constructeur.
    • Écrire des routes GET / POST, gérer les query params, body et route params.
    • Découper son code en modules fonctionnels plutôt qu'un seul gros AppModule.

    Ressources FR

    NestJS de A à Z — (1) Les bases 39 min Docs FR — Premiers pas Contrôleurs Fournisseurs Modules Alternative : module + controller + service 13 min

    Jalon 1 — une API GET /tasks et POST /tasks qui lit et écrit un tableau en mémoire, répartie en tasks.module.ts / tasks.controller.ts / tasks.service.ts.

  2. Étape 2 — DTO, Pipes de validation, Exceptions, Intercepteurs

    ~6 h
    • Créer des DTO et les valider avec class-validator + ValidationPipe.
    • Brancher le ValidationPipe globalement dans main.ts — une seule fois, pour toute l'app.
    • Lever des exceptions HTTP propres (NotFoundException) au lieu de renvoyer des messages en dur.
    • Écrire un interceptor (logging, temps de réponse, transformation de sortie).

    Ressources FR

    (2) Pipes, DTO, Exceptions et Guards 37 min Validation Pipelines Filtres d'exception Intercepteurs

    Jalon 2 — POST /tasks avec un CreateTaskDto renvoie 400 avec la liste précise des champs invalides ; GET /tasks/999 renvoie 404 ; un interceptor journalise la durée de chaque requête.

  3. Étape 3 — Base de données et configuration

    ~8 h
    • Brancher Prisma (recommandé) ou TypeORM sur une base PostgreSQL.
    • Modéliser les entités, écrire les migrations, générer les types TypeScript.
    • Isoler la configuration avec ConfigModule et un .env validé au démarrage.
    • Comprendre la différence entre PrismaService (provider) et un simple repository.

    Ressources FR

    Connecter une base avec Prisma 13 min Premier CRUD étape par étape 25 min Recette Prisma Configuration

    Jalon 3 — les tâches sont persistées en PostgreSQL. Le CRUD complet (create / read / update / delete + pagination) fonctionne, et l'app refuse de démarrer si une variable d'environnement manque.

  4. Étape 4 — Sécurité : JWT, Guards, rôles, durcissement HTTP

    ~8 h
    • Créer un module auth : register / login, hachage bcrypt, génération du JWT.
    • Protéger les routes avec un Guard global, puis gérer les rôles (@Roles) pour l'admin.
    • Ajouter Helmet, CORS restreint et le rate limiting (Throttler).
    • Ne jamais mal gérer le mot de passe : hash avec sel (bcrypt), jamais de SHA brut.

    Ressources FR

    Authentification JWT sécurisée 32 min (4) Sécurité : CORS, Helmet, CSRF, Rate limit 29 min Les Guards en pratique 23 min Authentification Limitation du taux

    Jalon 4 — POST /auth/login renvoie un token ; les routes /tasks sont inaccessibles sans token ; une route /admin exige le rôle admin ; le rate limit bloque au bout de N requêtes.

  5. Étape 5 — Tests et documentation de l'API

    ~5 h
    • Écrire un test unitaire d'un service (Jest, déjà installé par la CLI).
    • Écrire un test e2e qui démarre l'application et tape une vraie route HTTP.
    • Générer la doc Swagger / OpenAPI pour documenter toute l'API automatiquement.
    • Apprendre à mocker une dépendance (pas de base de données réelle dans les tests unitaires).

    Ressources FR

    Docs FR — Tests OpenAPI / Swagger Recette Swagger Cours officiel (EN, sous-titres) — chap. Tests

    Jalon 5 — npm test et npm run test:e2e passent au vert, et /api/docs affiche une documentation complète de ton API.

  6. Étape 6 — Industrialiser : structure, performance, déploiement

    ~6 h
    • Passer d'un projet unique à un monorepo (ou au moins séparer app et modules).
    • Découvrir ConfigModule avancé, le logging structuré, le cache et la planification de tâches.
    • Connaître les options de performance (Fastify, compression) et le health check (Terminus).
    • Avoir un Dockerfile et un docker-compose.yml qui lanquent l'app + la base.

    Ressources FR

    Espaces de travail (monorepo) Performance (Fastify) Mise en cache Vérifications de santé Cycle de vie des requêtes

    Jalon 6 — docker compose up démarre l'app et PostgreSQL ; un endpoint /health répond ; l'image se construit avec npm run build.

  7. Étape 7 — Spécialisation & projet final

    ~10 h
    • Choisir une specialization selon ton métier : GraphQL, WebSockets ou microservices.
    • Comprendre ExecutionContext, Reflector, les portée d'injection et les modules dynamiques.
    • Construire un projet complet de bout en bout, avec tests et documentation.
    • Savoir expliquer tes choix d'architecture en entretien.

    Ressources FR

    GraphQL — démarrage WebSockets — Passerelles Microservices — Aperçu Contexte d'exécution Générateur CRUD

    Jalon 7 — une API complète, sécurisée, testée et documentée, déployable. Tu es prêt pour un poste backend Node.js.

Le projet fil rouge

Un seul projet que tu fais grossir, étape par étape. C'est la méthode qui fait retenir — pas une nouvelle app à chaque tuto.

Étape 3

Étape 4

06

Les quatre pièges du débutant

Ce sont les erreurs qui reviennent le plus souvent — et celles qui coûtent le plus de temps.

Tout dans un seul module

Un AppModule qui grossit n'est pas de l'architecture. Un module par domaine, dès l'étape 1.

Logique métier dans le contrôleur

Le contrôleur ne fait que valider, déléguer, répondre. La logique vit dans le service — c'est ce qui rend le code testable.

Validation oubliée

Sans ValidationPipe global, n'importe quel JSON entre dans ta base. Une ligne dans main.ts règle le problème.

Sauter Nest et écrire du Express

Si tu écris app.get() dans main.ts, tu n'utilises plus Nest. Les routes passent par les contrôleurs et les modules.
